# SELECT

Compare worlds against the thesis, not generic polish. Explain strengths, risks and sacrifices. Allow hybrid selection, but articulate a new coherent hypothesis rather than a collage. If nothing has energy, diagnose thesis vs research vs divergence vs execution and route backward.

---

## Purpose
Choose which direction to develop further. SELECT is not "pick the prettiest"—it's evaluating which world best serves the thesis while identifying what would be sacrificed by each choice.

## Inputs
- 3–5 worlds from DIVERGE (with generated evidence)
- Creative thesis from POSITION
- User feedback (KEEP/REMOVE/PUSH from previous rounds)
- Any hard constraints (timeline, production capability, brand equity to preserve)

## Steps

### 1. Evaluate each world against the thesis
For each world, answer:
- Does this express the thesis? (not just "look good")
- What does this world do that others don't?
- What risk does this world carry?
- What would we sacrifice by choosing this?

### 2. Surface trade-offs explicitly
Don't hide sacrifices. Name them:
- "World A is bolder but riskier for enterprise sales"
- "World B is safer but less memorable"
- "World C is distinctive but harder to produce"

### 3. Allow hybrid selection (with new hypothesis)
If user wants elements from multiple worlds:
- **Don't** just collage: "Color from A, type from B, imagery from C"
- **Do** create a new coherent hypothesis: "What if we combined A's structural logic with B's warmth? New world: [name], premise: [one sentence]"

Hybrid must be a world, not a parts list.

### 4. Diagnose "nothing works" situations
If no world has energy, identify the failure:

| Symptom | Likely cause | Route to |
|---------|--------------|----------|
| All feel arbitrary | Thesis is too vague | POSITION |
| All feel similar | Divergence wasn't bold enough | DIVERGE (push harder) |
| All feel borrowed | Reference surfaces copied, not principles | REFERENCE |
| All feel weak | Not enough exploration | DIVERGE (more rounds) |
| User can't articulate preference | Thesis not internalized | POSITION (clarify) |

### 5. Lock the selection
Record the decision with rationale:
- Which world (or hybrid)
- Why this over others
- What we're sacrificing
- What we're committed to preserving (KEEPs from this world)

## Output shape
```
## Selection: Round [n]

### World evaluations
| World | Thesis fit | Strength | Risk | Sacrifice |
|-------|-----------|----------|------|-----------|
| [A] | [rating + note] | [note] | [note] | [note] |
| [B] | ... | ... | ... | ... |
| [C] | ... | ... | ... | ... |

### Recommendation
**Selected:** [World name or "Hybrid: X + Y"]
**Rationale:** [Why this best serves the thesis]
**Sacrifices acknowledged:** [What we're giving up]
**KEEPs locked:** [Non-negotiables from this selection]

### Next step
[CODIFY to formalize rules / more DIVERGE if hybrid needs testing / REFERENCE if world needs more territory]
```

## Quality gates
- [ ] Evaluated against thesis, not generic aesthetics
- [ ] Trade-offs named, not hidden
- [ ] Hybrid has a coherent hypothesis, not a parts list
- [ ] "Nothing works" diagnosed to a specific cause
- [ ] Selection rationale recorded for decision history

## Anti-patterns
- **Beauty pageant**: Picking the "best looking" without thesis evaluation
- **Franken-hybrid**: Collaging parts without a unifying idea
- **Avoiding sacrifice**: Pretending a choice has no downsides
- **Premature selection**: Choosing before enough divergence
- **Vague selection**: "Let's go with this vibe" without locking specifics

## When to route elsewhere
- No world fits thesis → POSITION (thesis may need revision)
- All worlds feel thin → REFERENCE (need more territory)
- User can't decide → may need more DIVERGE rounds
- Selection made → CODIFY to formalize the rules
